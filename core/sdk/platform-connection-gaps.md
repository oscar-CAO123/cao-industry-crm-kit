# Platform connection gaps

The kit's connection tests use a fake network. A client must supply its own credentials and complete the vendor's onboarding and any required certification before live use.

- **Microsoft Advertising:** The kit works inside one configured ad account. 191 Campaign Management operations and both Reporting operations are wired over Microsoft's REST routes (`campaign.api.bingads.microsoft.com`, `reporting.api.bingads.microsoft.com`), with the `CustomerAccountId` and `CustomerId` headers pinned to `MSADS_ACCOUNT_ID` and `MSADS_CUSTOMER_ID`. Before a request is sent the kit refuses: any account or customer ID field that is not those two, an entity ID list that names an account or customer, a campaign's parent that is another account, any `Scope` or `SharedEntityScope` other than `Account` (`Customer` reaches every account under the manager account), and a report request whose `Scope.AccountIds` is missing. Campaign, ad group and ad IDs are checked by Microsoft against the pinned `CustomerAccountId` header, not by the kit. Gets that return an auth key or a file link go through the write gate. The four UET tag operations stay refused (tags are shared by every account under the manager account). Customer Management (`clientcenter.api.bingads.microsoft.com`) allows five reads (GetAccount, GetCustomer, GetAccountPilotFeatures, GetCustomerPilotFeatures, GetCurrentUser); user, sign-up, client-link and cross-account calls stay refused. Native SDK requests remain refused. Routes come from Microsoft's [generated REST client](https://github.com/BingAds/BingAds-Python-SDK/tree/main/openapi_client); hosts and scope values from Microsoft Learn, for example [GetAccount](https://learn.microsoft.com/en-us/advertising/customer-management-service/getaccount?view=bingads-13) and [EntityScope](https://learn.microsoft.com/en-us/advertising/campaign-management-service/entityscope?view=bingads-13). Tested offline only.
- **SiteMinder:** Direct Booking is wired: its 13 read calls go to `https://directbooking.siteminder.com/public-api/api` with the `x-sm-api-key` header from `SITEMINDER_API_KEY`, a key the hotel generates itself (Platform, or MP Extranet for a group, under Direct Booking > API). [Direct Booking quick start](https://developer.siteminder.com/direct-booking-api/guides/quick-start.md). Channels Plus (`x-sm-api-id` and `x-sm-api-key`), SMX (Bearer token) and pmsXchange (Basic) are partner APIs for booking channels, subscribers and PMS vendors: credentials come from SiteMinder's Partner Portal after a signed partnership, only pre-production hosts are published, and some pmsXchange endpoints are called by SiteMinder on the PMS's own server. The kit refuses those 20 calls with that reason. [Integration process](https://developer.siteminder.com/get-started/partner-lifecycle/integration-process.md).
- **ServiceM8:** Add-on and messaging calls require a supplied `SERVICEM8_ADDON_ACCESS_TOKEN`; access tokens expire after one hour. OAuth authorization and refresh are not implemented by the kit. [ServiceM8 authentication](https://developer.servicem8.com/docs/authentication).
- **Dropbox:** Content uploads accept base64 file content up to 10 MiB per request. Larger transfers require chunked upload sessions. Native vendor SDK content calls remain refused by the SDK gate; use the kit's mapped operations. [Dropbox HTTP reference](https://www.dropbox.com/developers/paper-api-alpha).
- **Mailchimp Transactional:** Mapped calls take `MANDRILL_API_KEY` from the secret store and place it in the JSON request body. Native vendor SDK calls using this body-key scheme remain refused by the SDK gate. [Mailchimp Transactional authentication](https://mailchimp.com/developer/transactional/docs/fundamentals/).
